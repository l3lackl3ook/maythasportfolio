DATA INGESTION & API LIMITS

Meta Graph API 100-Post Pagination & Rate-Limit Wall

ขีดจำกัด Meta Graph API 100 โพสต์ & การติด Quota

Problem & Symptomปัญหาที่พบ

Meta Graph API caps post retrieval at 100 items per cursor page. Scraping active influencer archives frequently triggered HTTP 429 (Rate Limit Exceeded), causing pipeline timeouts and incomplete historical metrics.

Meta Graph API จำกัดการดึงโพสต์ไว้ที่ 100 รายการต่อหน้า เมื่อพยายามดึงข้อมูลย้อนหลังของ Influencer จึงติด HTTP 429 Quota Exceeded ทำให้ Pipeline ขาดตอนและข้อมูลไม่ครบ

Engineering Solutionวิธีแก้ปัญหา

Engineered an asynchronous tiered ingestion worker in Python FastAPI. Implemented exponential backoff with jitter, cursor state persistence in Redis, and a multi-engine fallback to Bright Data scraping proxies when official API quotas exhaust.

สร้าง Worker แบบ Asynchronous ด้วย Python FastAPI ใส่ระบบ Exponential Backoff with Jitter, เก็บ Cursor State ใน Redis และทำ Tiered Fallback สลับไปใช้ Scraping Proxy ผ่าน Bright Data ทันทีที่โควตาหลักเต็ม

Trade-off & Constraintsการตัดสินใจและข้อจำกัด

Proxy fallbacks carry per-gigabyte bandwidth cost. Configured a strict token/byte ledger with automated circuit-breakers to safeguard monthly budgets.

การสลับไปใช้ Proxy มีค่า Bandwidth จึงตั้งระบบ Token/Byte Ledger พร้อม Circuit Breaker อัตโนมัติเพื่อคุมงบประมาณไม่ให้บานปลาย

Measured Outcomeผลลัพธ์ที่วัดได้

Zero unhandled pipeline crashes; archive ingest success rate increased from 74% to 99.2% across 57K+ creator profiles.

ลดข้อผิดพลาดท่อข้อมูลหลุดเป็น 0; อัตราความสำเร็จในการซิงค์ข้อมูลย้อนหลังเพิ่มจาก 74% สู่ 99.2%

DATA QUALITY & DISAMBIGUATION

Brand Affinity OCR False Positives (e.g. Urban Revivo vs Vivo)

การแยกแยะ Brand Entity และแก้ False Positive (Urban Revivo vs Vivo)

Problem & Symptomปัญหาที่พบ

Substring-based tagging and early multimodal prompts confused overlapping brand names—flagging fashion brand "Urban Revivo" as smartphone maker "Vivo", polluting creator sponsorship classification.

การใช้ Substring Matching และ Prompt ตรวจจับแบรนด์แบบเดิมทำให้เกิด False Positive สูง เช่น แบรนด์เสื้อผ้า "Urban Revivo" ถูกจำแนกผิดเป็นแบรนด์มือถือ "Vivo" ส่งผลให้รายงานสปอนเซอร์เพี้ยน

Engineering Solutionวิธีแก้ปัญหา

Introduced a two-pass classification architecture: Fast Regex word-boundary filter followed by a constrained Gemini schema validator with contextual negative guards (industry vertical, surrounding token co-occurrence, and visual category check).

ออกแบบสถาปัตยกรรม Two-pass Validation: รอบแรกกรองด้วย Regex Word-Boundary และรอบสองส่งผ่าน Gemini Schema Validator พร้อม Negative Guards ตรวจสอบหมวดหมู่อุตสาหกรรมร่วม (Fashion vs Tech)

Trade-off & Constraintsการตัดสินใจและข้อจำกัด

Slightly increased per-caption inference latency (+18ms). Offset by caching verified brand entity signatures in PostgreSQL.

มี Latency เพิ่มขึ้นเล็กน้อย (+18ms) ซึ่งแก้ด้วยการทำ Entity Signature Cache บน PostgreSQL สำหรับโพสต์และแฮชแท็กที่ตรวจผ่านแล้ว

Measured Outcomeผลลัพธ์ที่วัดได้

False positive brand attribution dropped from 18.4% to below 1.2%, securing high data integrity for client campaign reporting.

ลดอัตราความคลาดเคลื่อน (False Positive) จาก 18.4% เหลือต่ำกว่า 1.2% สร้างความแม่นยำสูงให้ทีมและลูกค้านำไปวิเคราะห์ต่อ

Cloud FinOps: Slashing Gemini Multimodal Spend by 73%

วิศวกรรมควบคุมต้นทุน: ลดค่าใช้จ่าย Gemini API ลง 73%

Recurring multimodal video and thumbnail probes emitted giant 8,192-token JSON schemas. As the creator database expanded past 50K, monthly GCP billing threatened to outpace department budget limits.

การรัน Multimodal Probe ตรวจจับวิดีโอและภาพปกเดิมกำหนด Output Schema ไว้กว้างถึง 8,192 tokens เมื่อฐานข้อมูลครีเอเตอร์ทะลุ 50,000 โปรไฟล์ ค่าบริการ GCP Billing จึงเริ่มพุ่งสูงเกินงบประมาณที่ตั้งไว้

Engineering Solutionวิธีแก้ปัญหา

Redesigned extraction schemas into compact 2,048-token typed representations. Aligned Celery Beat snapshot intervals, introduced hash-based diffing to skip unchanged creator profiles, and added automated daily budget ceilings.

ปรับโครงสร้าง Output Schema ให้กะทัดรัดและตรงจุดเหลือเพียง 2,048 tokens จัดรอบการรัน Celery Beat ให้เป็นระบบ พร้อมใช้ Content Hash Diffing ข้ามการสแกนโปรไฟล์ที่ไม่มีการเปลี่ยนแปลง

Trade-off & Constraintsการตัดสินใจและข้อจำกัด

Removed non-essential secondary NLP tags (e.g. ambient lighting adjectives) to protect core business attributes (pricing, category, engagement).

ตัด Tag คำบรรยายเสริมที่ไม่จำเป็นต่อการวิเคราะห์การตลาดออก เพื่อคงข้อมูลสำคัญทางธุรกิจไว้ครบถ้วน

Measured Outcomeผลลัพธ์ที่วัดได้

Reduced Gemini API spend from ฿3,937.72 down to ฿1,068.57 per evaluation cycle (−73% drop) verified in GCP billing console.

ลดค่าบริการ Gemini API จาก ฿3,937.72 เหลือ ฿1,068.57 ต่อรอบการวัดผล (ลดลง 73%) ยืนยันจาก GCP Billing จริง
