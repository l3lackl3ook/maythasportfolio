How I handle API pagination walls, entity disambiguation, stateless security, and metric accuracy.

CASE 01 · MUSTHERD DATA INGESTION

Meta Graph API 100-Post Limit & Multi-Lane Fallback

แก้ข้อจำกัด Meta Graph API 100 โพสต์ & ระบบสลับช่องทางสำรอง

Problem Social APIs cap pagination at 100 posts/request and enforce strict rate limits, causing incomplete historical creator metrics. Social API จำกัดการดึงโพสต์สูงสุด 100 โพสต์/คำขอ และติด Rate Limit บ่อย ทำให้ข้อมูลย้อนหลังของครีเอเตอร์ขาดช่วง
Solution Split collection by account tier: routed business accounts via Meta Graph API with Redis cursor checkpoints, and public profiles via a free-lane scraper with Bright Data fallback. แยกวิธีดึงตามประเภทบัญชี: ใช้ Meta Graph API คู่กับ Redis Cursor สำหรับบัญชี Business และสลับไปใช้ช่องทางสำรองเมื่อติดโควตา
Trade-off Proxy fallbacks cost per-GB bandwidth; added budget guards so paid proxies only trigger for active campaign creators. Proxy สำรองมีต้นทุนตามปริมาณข้อมูล จึงตั้งตัวคุมโควตาให้เปิดใช้เฉพาะครีเอเตอร์ที่อยู่ในแคมเปญสำคัญ
Result 100 IG Business posts/request and 2.5× post coverage on the free lane in testing, reaching 99.2% sync completion. ดึงข้อมูลได้เต็ม 100 โพสต์/คำขอ สำหรับ IG Business และเพิ่มความครอบคลุมโพสต์ขึ้น 2.5 เท่าจากการทดสอบจริง
CASE 02 · DATA QUALITY & AI GUARDRAILS

Brand Affinity Disambiguation (Urban Revivo vs. Vivo)

แก้ปัญหา AI จำแนกชื่อแบรนด์สับสน (Urban Revivo vs. Vivo)

Problem Substring matching and unconstrained LLM prompts misclassified fashion brand "Urban Revivo" as smartphone maker "Vivo". การเช็กคำซ้อนทับและการถาม AI แบบไม่มีกรอบควบคุม ทำให้แบรนด์เสื้อผ้า "Urban Revivo" ถูกตรวจจับผิดเป็นมือถือ "Vivo"
Solution Built a 2-pass filter: regex word-boundary & negative-lexicon pre-check, followed by constrained Gemini schema validation requiring category alignment (Apparel vs. Tech). สร้างตัวกรอง 2 ชั้น: ใช้ Regex Word-Boundary ตัดคำซ้อนทับ แล้วตรวจซ้ำด้วย Gemini Schema ที่บังคับเช็กหมวดหมู่อุตสาหกรรม
Trade-off Slight latency increase on new captions; offset by caching verified brand-entity pairs in PostgreSQL. ใช้เวลาประมวลผลเพิ่มเล็กน้อยในโพสต์ใหม่ ซึ่งชดเชยด้วยการทำ Cache คู่แบรนด์ที่ตรวจแล้วลงใน PostgreSQL
Result Reduced false-positive brand tags from 18.4% to under 1.2% on audited samples. ลดอัตราการจับคู่แบรนด์ผิดพลาดจาก 18.4% เหลือต่ำกว่า 1.2% ทำให้ข้อมูลนำไปใช้งานต่อได้แม่นยำ
CASE 03 · DENCRM WORKFLOW ARCHITECTURE

Stateless 1-Click CEO Lead Approval via HMAC Gmail

ออกแบบปุ่มกด Approve แจก Lead ใน Gmail แบบไม่ต้องล็อกอิน

Problem Requiring the CEO to open a browser and log into the CRM for every new website lead slowed down sales handoffs. การที่ผู้บริหารต้องเปิดเบราว์เซอร์ล็อกอินเข้าเว็บทุกครั้งที่มี Lead ใหม่เข้ามา ทำให้การส่งต่อลูกค้าให้เซลส์ล่าช้า
Solution Embedded HMAC-SHA256 signed URLs (leadId.salesEmail.assignerEmail.exp) into Nodemailer Gmail alerts for 1-click rep assignment. สร้างลิงก์เข้ารหัส HMAC-SHA256 ฝังในปุ่มอีเมลที่ส่งเข้า Gmail เพื่อให้ CEO กดเลือกชื่อเซลส์เพื่อจ่ายงานได้ทันที
Trade-off 14-day token TTL balances weekend inbox convenience with strict RBAC verification and idempotent click handling. กำหนดอายุลิงก์ 14 วันเพื่อให้เมลช่วงวันหยุดยังกดได้ พร้อมตรวจสิทธิ์ RBAC และป้องกันการกดซ้ำ
Result Cut executive lead-assignment time to under 5 seconds directly inside mobile Gmail. ลดเวลาการอนุมัติและแจก Lead ของผู้บริหารเหลือไม่ถึง 5 วินาทีผ่านแอป Gmail บนมือถือ
CASE 04 · METRIC RELIABILITY & FINOPS

ER Normalization & −73% Gemini Token Optimization

มาตรฐานสูตรคำนวณ ER & การบีบอัด Schema ลดต้นทุน AI 73%

Problem Outlier viral posts skewed creator Engagement Rates (ER), while 8,192-token Gemini probes drove high GCP costs. โพสต์ไวรัลบางโพสต์ดึงค่าเฉลี่ย ER เพี้ยน และการตั้ง Output Schema กว้างถึง 8,192 Tokens ทำให้ค่าใช้จ่ายคลาวด์พุ่งสูง
Solution Normalized ER formulas per platform with outlier trimming, and compressed Gemini schemas to 2,048 tokens with SHA-256 diffing. ปรับสูตร ER แยกตามแพลตฟอร์มพร้อมตัดค่าเพี้ยน และลดขนาด Schema เหลือ 2,048 Tokens ร่วมกับการเช็ก Hash ก่อนรัน
Trade-off Stores post-level snapshots in PostgreSQL so every metric remains traceable back to its source post. เก็บข้อมูลรายโพสต์ลงฐานข้อมูลเพื่อให้ตรวจสอบย้อนกลับได้เสมอว่าตัวเลข ER คำนวณมาจากโพสต์ใด
Result Slashed Gemini API billing by 73% (฿3,937.72 → ฿1,068.57) and stabilized creator ER reporting. ลดค่าใช้จ่าย Gemini API ลง 73% จากบิลจริง และทำให้ข้อมูล ER แม่นยำเชื่อถือได้
